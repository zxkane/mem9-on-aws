# Test cases: workload permissions boundary

Design:
[`docs/designs/workload-permissions-boundary.md`](../designs/workload-permissions-boundary.md)

## Scope Parsing And Matching

| ID                  | Scenario                                                                                     | Expected                                                                     |
| ------------------- | -------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| TC-IAM-BOUNDARY-001 | Read paginated managed and inline deploy-role policies                                       | Every page and policy version contributes to one canonical PassRole scope    |
| TC-IAM-BOUNDARY-002 | Policy has the three supported project role patterns                                         | Scope is accepted and normalized independent of statement or array order     |
| TC-IAM-BOUNDARY-003 | PassRole uses `Resource: "*"`, an interior wildcard, `NotResource`, or an unknown prefix     | Parsing fails closed before role enumeration                                 |
| TC-IAM-BOUNDARY-004 | Allow uses `iam:*`, `*`, `NotAction`, or an unknown action pattern that can include PassRole | Parsing fails closed rather than overlooking a grant                         |
| TC-IAM-BOUNDARY-005 | PassRole targets an unsupported service or omits the service condition                       | Parsing fails closed                                                         |
| TC-IAM-BOUNDARY-006 | Role names exercise full and SST-truncated prefixes                                          | Only roles matched by the deployed PassRole patterns enter the migration set |
| TC-IAM-BOUNDARY-007 | A list/get-policy call fails or pagination repeats a marker                                  | Discovery stops before enforcement                                           |

## Rollout State Machine

| ID                  | Scenario                                                           | Expected                                                                                                                                                   |
| ------------------- | ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TC-IAM-BOUNDARY-008 | Full rollout                                                       | Calls follow quarantine -> boundary deploy -> discover -> migrate -> read back -> rediscover -> enforce -> production activation -> verify -> unquarantine |
| TC-IAM-BOUNDARY-009 | Quarantine installation fails                                      | No discovery, role mutation, enforcement, or quarantine removal occurs                                                                                     |
| TC-IAM-BOUNDARY-010 | Boundary attachment fails partway                                  | Rollout stops immediately and quarantine remains installed                                                                                                 |
| TC-IAM-BOUNDARY-011 | Boundary read-back is missing or different                         | Permanent enforcement is not deployed and quarantine remains                                                                                               |
| TC-IAM-BOUNDARY-012 | PassRole scope changes between reads                               | Rollout fails before permanent enforcement and leaves quarantine installed                                                                                 |
| TC-IAM-BOUNDARY-013 | Permanent stack update or verification fails                       | Quarantine remains and output contains only a redacted resume command                                                                                      |
| TC-IAM-BOUNDARY-014 | Successful rollout                                                 | Production activation is read back; quarantine deletion and absence are both verified before it becomes the final IAM mutation                             |
| TC-IAM-BOUNDARY-015 | Resume after partial migration                                     | Already bounded roles are verified, remaining roles are migrated, and no unsafe detach occurs                                                              |
| TC-IAM-BOUNDARY-016 | Role inventory is paginated                                        | Every matching role is migrated exactly once                                                                                                               |
| TC-IAM-BOUNDARY-017 | Rewrite the real rollout module to move quarantine after discovery | The imported mutation fails the ordering invariant                                                                                                         |
| TC-IAM-BOUNDARY-018 | Rewrite the real rollout module to accept a missing boundary       | The imported mutation fails the coverage invariant                                                                                                         |

## CloudFormation And Deploy-Role Policy

| ID                  | Scenario                                                 | Expected                                                                                                                                                                                              |
| ------------------- | -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TC-IAM-BOUNDARY-019 | Parse the boundary template                              | One retained customer managed policy uses the fixed name, one broad identity allow, and an explicit `Deny`/`NotAction` runtime ceiling                                                                |
| TC-IAM-BOUNDARY-020 | Inspect boundary action ceiling                          | Every action outside the reviewed ECS, Lambda, AgentCore, alert-router, OAuth, and Mantle runtime set is explicitly denied, including IAM, STS, CloudFormation/Cloud Control, and ECR scanning writes |
| TC-IAM-BOUNDARY-021 | Inspect runtime resource and condition guards            | Project-capable actions are denied outside project resources; KMS decrypt requires either the project Parameter Store path or a project Lambda function context, with direct function-code and non-Lambda forgery denied; Mantle bearer use is short-term only |
| TC-IAM-BOUNDARY-022 | Inspect deploy-role CreateRole and boundary-write grants | Both require the exact boundary ARN                                                                                                                                                                   |
| TC-IAM-BOUNDARY-023 | Inspect deploy-role policy-write grants                  | `PutRolePolicy` and `AttachRolePolicy` require the exact boundary on the target role                                                                                                                  |
| TC-IAM-BOUNDARY-024 | Inspect cleanup grants                                   | Read, detach, inline-policy delete, and role delete remain; `DeleteRolePermissionsBoundary` is denied                                                                                                 |
| TC-IAM-BOUNDARY-025 | Inspect operator-owned resource guards                   | Boundary policy plus boundary, deploy-role, and ECR ownership stacks are immutable to the deploy role                                                                                                 |
| TC-IAM-BOUNDARY-026 | Validate both out-of-band templates                      | Strict `cfn-lint` reports no errors or warnings in the IAM stack region                                                                                                                               |
